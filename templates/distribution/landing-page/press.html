Press kit

For journalists, podcast hosts, conference organisers, and partners.

One-liner

Roam gives coding agents reusable local code analysis and checks: code connections to query, algorithmic alternatives to investigate, and check results to act on.

Two-paragraph blurb

Roam equips the coding agent a developer already uses with a local code index and built-in analyses. The agent can query function callers, inspect a detected pattern alongside a catalogued alternative, and check a proposed change. It gets source locations and scoped results to use in its next step, instead of implementing every analysis itself. Refresh the index as code changes. Agents call the tools through the command line or MCP, the protocol for connecting tools to an agent. Roam's static analysis runs locally without model calls; a connected agent's own model usage and data handling are separate.

The tools are free and open source under Apache 2.0. With the run ledger and proof-bundle workflow enabled, Roam can also save records of checks for later review. Those records do not replace tests, prove runtime safety, or certify compliance. Paid PR Replay reports offer help interpreting a named scope; hosted Roam Review and Roam Cloud are planned, not available to subscribe to. Roam is built in Athens by Dimitris, known as Cranot on GitHub.

Voice notes

  • Plain English. No marketing buzzwords. No "delightful," "robust," "synergy," "supercharge," "leverage."
  • Name the work. Roam returns code locations and findings; the agent investigates them and people decide what ships.
  • Use a concrete example with its scope. A caller count describes the connections found, not proof that every connection was found.
  • Honest about gaps. We say what we don't have, not just what we do.
  • EU + privacy-first is real positioning, not garnish.
